# stepord / mstepord

대화형으로 매수/매도, 가격, 수량을 입력받아 주문 1건을 매칭엔진에 전송하고 응답을 확인하는 수동 단계별(step-by-step) 검증용 도구. 지정가/시장가 버전 2개가 각각 독립 `main()`으로 존재한다.

- `stepord.go` → 지정가 주문(`OrdType: "L"`, `UserId: "42280"`)
- `mstepord.go` → 시장가 주문(`OrdType: "M"`, `UserId: "42281"`)

두 파일 모두 `package main`이며 **같은 디렉토리에서 함께 빌드할 수 없다** (중복 `main`/`getInput` 선언 충돌). 반드시 파일을 하나씩 지정해서 빌드/실행해야 한다.

## 개요

콘솔에서 `매수:B, 매도:S`, `주문가격`, `주문수량`을 순서대로 입력받고(`Q`/`q` 입력 시 즉시 종료), `Mb.OrderJson`(심볼 `BTC.USDT`, 채널 `CN03` 고정)을 조립해 ZMQ REQ로 `tcp://127.0.0.1:31001`(하드코딩)에 전송한 뒤 응답을 출력한다. 매칭엔진에 주문을 하나씩 수동으로 넣어가며 매칭 결과를 눈으로 확인할 때 사용한다.

## 빌드 / 실행

Makefile 없음.

```bash
cd "goPlus/tools/매칭검증/stepord"

# 지정가 버전
go run stepord.go
# 또는: go build -o stepord stepord.go && ./stepord

# 시장가 버전
go run mstepord.go
# 또는: go build -o mstepord mstepord.go && ./mstepord
```

## 사용법

실행 후 프롬프트에 순서대로 입력:

```
매수:B, 매도:S -  B
주문가격  95000
주문수량  0.001
```

세 프롬프트 중 어디서든 `Q`/`q`를 입력하면 전송 없이 종료한다.

## 환경설정

- 없음(모든 값을 대화형 입력으로 받음). 단, REQ 엔드포인트(`tcp://127.0.0.1:31001`)와 심볼(`BTC.USDT`)·종목코드(`441`)·시장코드(`2965`) 등은 **소스에 하드코딩**되어 있어 다른 대상에 사용하려면 코드를 직접 수정해야 한다.

## 주의사항

- 하드코딩된 엔드포인트가 운영 매칭엔진을 가리키면 실주문이 들어갈 수 있다 — 테스트 환경에서만 사용할 것.
- `UserId`는 고정값(`42280`/`42281`)이며 코드 내 `uid`(무작위 생성) 변수는 만들어지지만 실제로는 사용되지 않는다(주석 처리된 `UserId: uid` 대신 고정 문자열 사용) — 죽은 코드로 남아있다.
- 응답 파싱을 하지 않고 원본 메시지를 그대로 출력하므로, 주문이 실제로 성공했는지는 출력된 `REP` 내용을 직접 읽고 판단해야 한다.
